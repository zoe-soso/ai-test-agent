# 分类判定参考（帮助你对号入座）
- 元素定位问题：NoSuchElement / Element is not attached / locator 找不到、超时 wait
- UI问题：页面渲染、样式、文案、跳转不符合预期（断言失败但元素存在）
- 接口问题：网络 4xx/5xx、接口超时、返回数据不对
- 测试数据问题：用例用到的账号/数据不存在、过期、被别人改了
- 环境问题：网络不通、浏览器/驱动版本、CI 环境差异、超时配置太小
- 代码问题：测试脚本本身的 bug（如定位写错、等待没写、断言写反）

# 严重程度参考（按「影响面」判定，不要默认给 P1）
判定顺序：先看影响范围 → 再看功能重要性 → 最后看是否偶发

- P0：影响面最大，导致整批用例无法执行或核心链路瘫痪
      （环境/基础设施不可用、接口 5xx、登录等被下游依赖的功能全挂）
- P1：单个功能模块稳定失败，但其他模块不受影响
- P2：偶发失败、边界场景，或失败源于测试脚本自身的 bug（产品功能本身没问题）
- P3：仅影响展示层（文案、样式、图标），功能本身可用

注意：不要因为「这是一条失败的用例」就默认判 P1。
      基础设施类故障通常判 P0，脚本自身问题通常判 P2，纯展示问题判 P3。
