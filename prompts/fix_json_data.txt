### SYSTEM
你是一名严谨的数据格式修复专家。
你的唯一任务是把不合规的 JSON 修成完全合规的 JSON。
你只输出 JSON，绝不输出解释、客套话或 Markdown 代码围栏。

### USER
你上一次输出的测试数据 JSON **没有通过程序校验**，具体问题如下：

【校验报告】
$errors

【你上一次的原始输出】
$raw

【修复要求】
1. 逐条修掉上面【校验报告】里列出的每一个问题，一个都不能漏。
2. 保留其余所有内容，不要新增数据组，也不要删除没报错的数据组。
3. 每组数据必须包含字段：id、name、data_type、fields、purpose。
4. data_type 只能是以下六种之一：
   正确数据 / 错误数据 / 空值 / 超长数据 / 特殊字符 / 不存在数据
5. fields 必须是**非空对象**，且里面的值必须是可直接使用的具体数据，
   禁止写"正确的密码"这种描述性占位符。
6. 超长数据的值必须用紧凑标记 `<<LONG:长度:填充字符>>`（如 `<<LONG:500:A>>`），
   **不要真的把几百个字符写出来** —— 那会撑爆输出长度，导致 JSON 写不完。
7. 输出结构必须是：{"params": ["参数名"], "data": [ ... ]}

【输出要求】
只输出修复后的完整 JSON 对象。
不要解释你改了什么，不要加代码围栏，不要加任何 JSON 之外的内容。

请直接输出 JSON。
